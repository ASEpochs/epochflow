这份说明用于求职、科研申请和技术交流。所有表述都对应当前仓库中的实际实现，面试时可以直接打开代码或线上系统验证。

## 30 秒项目介绍

EpochFlow 是我设计并实现的可观测多 Agent 平台。它把意图识别、结构化路由、专业 Agent、动态 Skills、知识检索、工具调用和质量评测串成完整链路，并提供一个多模型实验中心，统一接入文字、多模态生成、Embedding 与 Rerank 能力。前端使用 Vue，后端使用 FastAPI，已部署为无需登录的在线作品集。

## 为什么不是普通聊天 Demo

普通聊天 Demo 通常是“输入一句话 → 调用一次模型 → 显示文本”。EpochFlow 在调用前后增加了可验证的工程层：

1. **先理解任务：** 融合规则、模板与模型判断，输出细粒度意图、实体和置信度。
2. **再分配职责：** 依据意图、紧急程度和运行表现选择主 Agent 与辅助 Agent。
3. **限制可执行能力：** 每个 Agent 只能调用白名单中的工具，并校验工具参数。
4. **注入业务知识：** Skills 与检索结果按需进入上下文，避免所有资料无差别塞给模型。
5. **保留执行证据：** 返回 request_id、路由理由、工具输入输出与耗时。
6. **持续验证质量：** 通过意图用例和 LLM-as-Judge 评测发现回归。

## 值得展开讲的三个技术点

### 请求级模型隔离

模型中心允许用户在并发请求中切换模型。如果直接修改全局模型字段，会让另一个会话错误地使用当前用户选择的模型。项目使用 `ContextVar` 保存请求级模型选择，并在请求结束或异常时恢复上下文；测试覆盖并发工具调用往返和失败后的清理。

对应代码：`backend/core/model_scope.py`、`backend/tests/test_model_studio.py`。

### Anthropic 工具块与 OpenAI Function Calling 转换

Agent 编排器内部使用 Anthropic 风格的 `text / tool_use / tool_result` 内容块。切换到 OpenAI 兼容模型时，网关会转换 system、messages、tools、tool_calls 和工具结果，再把响应还原为编排器可识别的结构。这样无需为每个模型复制一套 Agent 逻辑。

对应代码：`backend/core/model_scope.py`、`backend/core/llm_utils.py`。

### 免费部署下的架构取舍

公开作品集不使用持久磁盘、Redis 或 ChromaDB。云端版本使用有上限的进程内记忆和字符 n-gram 检索，换取零数据库成本和简单部署；界面明确提示数据会随服务重启清除。Embedding 与 Rerank 保留为独立实验，不伪装成免费知识库的默认实现。

对应代码：`backend/memory/free_memory.py`、`backend/mcp/free_knowledge.py`、`render.yaml`。

## 推荐演示脚本

### 5 分钟版本

1. 在对话实验室发送一个包含技术和账单诉求的问题。
2. 展开执行面板，说明意图、主辅 Agent 和工具记录。
3. 在知识空间新增一篇资料并执行检索。
4. 打开模型中心，展示 50 个模型的分类和实时状态。
5. 运行一次 Embedding 或 Rerank 实验，说明不同模型能力使用不同 API。
6. 打开评测实验，说明系统如何验证迭代质量。

### 1 分钟版本

只展示一次多诉求对话及执行面板，然后打开模型中心。重点说明：“这个项目关注 Agent 如何路由、调用工具和被评测，而不只是最终回答。”

## 常见面试问题

### 为什么需要多个 Agent？

重点不是增加角色数量，而是隔离提示词、工具权限和业务规则。账单 Agent 不应拥有技术诊断工具，技术 Agent 也不应随意执行退款类操作。结构化路由让职责边界可以被观察和测试。

### 为什么不直接用一个大模型判断所有事情？

全模型判断成本更高、延迟更大且结果波动。EpochFlow 将本地信号与模型结果组合，并缓存稳定的意图结果；无法可靠判断时走明确的降级路径。

### 如何避免模型切换影响其他用户？

模型选择保存在请求上下文，不修改全局配置；请求完成和异常都会重置。并发单元测试验证两个模型的工具调用不会串线。

### 免费版本为什么不用向量数据库？

这是部署成本与展示目标之间的取舍。当前免费实例没有持久磁盘，使用轻量检索可以确保项目稳定启动并清楚展示检索链路。完整向量能力通过模型中心的 Embedding 与 Rerank 实验展示，未来可以替换为托管向量数据库。

### 系统目前最大的限制是什么？

公开访客共享临时内存，没有用户账户隔离；Render 休眠会清除数据；业务工具是教学数据；模型费用与可用性依赖供应商。项目没有把这些限制隐藏，而是在界面和文档中明确标注。

## 可继续迭代的方向

- 接入托管 PostgreSQL + pgvector，实现用户隔离和持久知识库；
- 增加 OpenTelemetry trace，将 Agent、模型和工具耗时统一关联；
- 为路由策略加入离线数据集、混淆矩阵和自动回归门禁；
- 增加流式响应与可取消任务；
- 将示例业务工具替换为经过授权的真实服务连接器；
- 为高成本模型增加按用户配额、预算和审计记录。
