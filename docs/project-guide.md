# EpochFlow 项目导览与设计说明

[返回项目首页](../README.md) · [English README](../README_EN.md) · [在线体验](https://epochflow-web.onrender.com/)

这份文档用于快速理解 EpochFlow 的目标、设计范围、关键技术取舍和使用路径。文中的能力均对应当前仓库实现，可以通过线上系统、源码和自动化测试进行验证。

## 项目概览

EpochFlow 是一个可观测的多 Agent 运行与模型实验平台。它把意图识别、结构化路由、专业 Agent、动态 Skills、知识检索、工具调用和质量评测串成完整链路，并提供模型中心，统一接入文字、多模态生成、Embedding 与 Rerank 能力。

系统由 Vue 前端和 FastAPI 后端组成，公开版本部署在 Render，无需注册或访问码即可使用。免费运行配置采用临时内存，不依赖持久磁盘、Redis 或 ChromaDB。

## 为什么使用多阶段 Agent 链路

一次普通模型调用通常只有“输入文本—生成文本”。EpochFlow 在调用前后增加了可验证的工程层：

1. **理解任务：** 融合规则、模板与模型判断，输出细粒度意图、实体和置信度。
2. **分配职责：** 依据意图、紧急程度和运行表现选择主 Agent 与辅助 Agent。
3. **约束能力：** 每个 Agent 只能调用白名单中的工具，并校验工具参数。
4. **补充上下文：** Skills 与检索结果按需进入上下文，避免无关资料占用窗口。
5. **保留证据：** 返回 request_id、路由理由、工具输入输出与耗时。
6. **验证质量：** 通过意图用例和 LLM-as-Judge 评测发现功能回归。

## 三个核心设计

### 请求级模型隔离

模型中心允许不同请求选择不同模型。如果直接修改全局模型字段，并发会话可能读取到其他请求的模型配置。项目使用 `ContextVar` 保存请求级模型选择，并在请求结束或异常时恢复上下文；测试覆盖并发工具调用往返和失败后的清理。

对应代码：`backend/core/model_scope.py`、`backend/tests/test_model_studio.py`。

### Anthropic 与 OpenAI 工具协议转换

Agent 编排器内部使用 Anthropic 风格的 `text / tool_use / tool_result` 内容块。切换到 OpenAI 兼容模型时，网关会转换 system、messages、tools、tool_calls 和工具结果，再把响应还原为编排器可识别的结构。这样可以共用同一套 Agent 逻辑。

对应代码：`backend/core/model_scope.py`、`backend/core/llm_utils.py`。

### 免费部署下的存储取舍

公开版本不使用持久磁盘、Redis 或 ChromaDB。云端服务使用有上限的进程内记忆和字符 n-gram 检索，降低部署依赖；界面明确提示数据会随服务重启清除。Embedding 与 Rerank 作为独立模型实验提供，不作为免费知识库的默认实现。

对应代码：`backend/memory/free_memory.py`、`backend/mcp/free_knowledge.py`、`render.yaml`。

## 使用路线

### 完整体验

1. 在对话实验室发送一个同时包含技术和账单诉求的问题。
2. 展开执行面板，查看意图、主辅 Agent、路由理由和工具记录。
3. 在知识空间新增一篇资料并执行检索。
4. 打开模型中心，按类别浏览模型及实时可用状态。
5. 运行一次 Embedding 或 Rerank 实验，观察不同能力对应的请求结构。
6. 打开评测实验，创建测试用例并查看质量报告。

### 快速体验

执行一次混合诉求对话并打开执行面板，然后进入模型中心浏览任务分类。两处页面分别展示 Agent 编排链路和多模型接入能力。

## 设计问题

### 为什么需要多个 Agent？

多个角色用于隔离提示词、工具权限和业务规则。账单 Agent 不应拥有技术诊断工具，技术 Agent 也不应执行退款类操作。结构化路由让这些职责边界可以被观察和测试。

### 为什么不让一个模型处理所有判断？

完全依赖模型判断会增加成本、延迟和结果波动。EpochFlow 将本地规则信号与模型结果组合，并缓存稳定的意图结果；无法可靠判断时进入明确的降级路径。

### 如何避免模型切换影响其他用户？

模型选择保存在请求上下文，不修改全局配置；请求完成和异常都会重置。并发单元测试验证多个模型请求及工具调用不会串线。

### 免费版本为什么不用向量数据库？

当前公开实例没有持久磁盘，轻量检索可以保证项目稳定启动并展示完整检索链路。Embedding 与 Rerank 实验仍保留，后续可以将默认检索替换为托管向量数据库。

### 当前版本有哪些边界？

公开访客共享临时内存，Render 休眠会清除数据；订单、退款等工具使用演示数据；模型费用与可用性依赖供应商。界面和文档均会标明这些边界。

## 可继续迭代的方向

- 接入托管 PostgreSQL + pgvector，实现用户隔离和持久知识库；
- 增加 OpenTelemetry trace，将 Agent、模型和工具耗时统一关联；
- 为路由策略加入离线数据集、混淆矩阵和自动回归门禁；
- 增加流式响应与可取消任务；
- 将示例业务工具替换为经过授权的真实服务连接器；
- 为高成本模型增加按用户配额、预算和审计记录。
